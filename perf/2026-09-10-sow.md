# Trend reading at virglrs sync-on-leave

**Subject:** virglrs `5582aa3` (sync-on-leave, unpushed) with host mesa `limina-kk` `351a1b5e`
(a shared context's fence flushes async instead of draining; local), on limina `6b0af433`.
Evidence in `perf/evidence/2026-09-10-sow/`. HVF suite **138/138** at this tree.

**A trend reading, not an attribution.** The previous rows are at virglrs `4654a34`, so this window
spans more than sync-on-leave: the virglrs commits up to `d0416c9` and a host mesa move are in it
too. The change itself was priced by direct instruments, below, and by the virglrs session's own
A/B.

**Shader Pipeline is a lead, not a finding.** It spreads about 10% between boots, but both boots
landed under the whole previous band, roughly 10-15% down. The window contains more than
sync-on-leave, so it is not attributed. It is a classic-path test, and a third pair of boots at
each end of the window would settle it.

**A candidate mechanism, with the measurement that tests it.** Sync-on-leave takes a `glFenceSync` on
every context departure, whether or not a fence ever collects it (`Current::switch_to`, virglrs
`src/vrend/context.rs:181`). So a hop costs one sync where it used to cost one `eglMakeCurrent`, and a
workload whose hops far outnumber its fences pays more than before, the opposite of vkmark and the
desktop, which both fence often. Read `VIRGLRS_SUBMIT_STATS=5` under Shader Pipeline alone and compare
**hops per fence** with vkmark's. If it is much higher there, the departure sync should become
conditional. If it is similar, the cause lies elsewhere in the window.

## Method

Only the llvmpipe control is entitled to call the host quiet. It stayed in band throughout (725.7 –
734.5). Every guest was gated on uptime ≥ 180-240 s and a 1-minute load under 0.3 before measuring.
`VIRGLRS_SUBMIT_STATS` was set on the A/B legs only, never on the battery, to match the baseline.
The host zink-on-KK prefix was rebuilt at `351a1b5e`, and the patched `syncobj.c` was force-
recompiled so the build could not be stale.
