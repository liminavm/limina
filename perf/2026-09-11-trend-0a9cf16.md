# Where the battery went across virglrs 0a9cf16..d0416c9

**A coarse map, not an attribution.** Ten points plus the baseline, one boot pair each, across the
151 first-parent virglrs commits from `0a9cf16` (09-08) to `d0416c9` (09-10). Large moves between
neighbouring points were probed down to a commit or a cluster; small ones were left alone. Rows are
in `trend-0a9cf16/ledger.csv`, never in `ledger.csv`.

## What moved, and where

- **p00 → p01, aquarium −40%, Geometry −20%, Canvas −17%: `894b36d`** ("vrend: make a classic fence
  wait for the GL work it fences"). The only vrend commit in the step; with it alone on the baseline
  (`b1`), aquarium reads 20/24, 20/20 — p01's level, not p00's. Basemark did not score on that boot.
- **p02 → p03, aquarium back to the baseline: the classic-fence rework** (`0c38b13`, `53c752a`,
  `cec8911`, `4afa3ef`) with libkrun `7c4ada0`. The two cannot be separated: `4afa3ef`'s
  `create_fence` takes the fence's context, and only `7c4ada0` passes it (`b3` does not build), so
  libkrun's half is the plumbing. Geometry Stress also recovers part of its drop here (1442–1473 at p02
  on three boots, 1613 at p03).
- **p03 → p04, aquarium +30% over the baseline: the command-path batch** (`fea5565..d30b8ce` —
  hash tables, sampler binds without allocating, feature bits, journal-slot refill, sysval
  generations, skipped `glUseProgram`, the draw's program resolved once). Not `7c65f0f`, the page-flip
  drain fix that precedes it: with that alone (`b2`) aquarium stays at p03's 35/37, 30/30.
  At the batch's midpoint (`00657a4`, `b4`) aquarium reads 42/40 at 25k and 29/30 at 30k — about half
  the 25k gain and none of the 30k — so most of it lands in `ee2f171..d30b8ce`. That boot was
  contended (gl-replay-venus 54.8–56.1 against 56.7 everywhere else, control down to 703), so read the
  split as indicative.
- **p06 → p07, Canvas back to the baseline (987 → 1174): two fence changes, `39b0c68` and
  `1fd19c2`.** At `1fd19c2` with p06's libkrun, Canvas already reads 1180 and 1160 (`s10`, `s11`), so
  the recovery is not the parked present (`4654a34`, libkrun `bae5de4a`). The only vrend commits in `4bfdefe..1fd19c2` are `39b0c68` ("a fence with no work of
  its own rides the queue, not a full drain"), `c77798a` (counters) and `1fd19c2` ("a fence covers
  every queue its work could be on"); the rest are harness changes this sweep does not run.
- **WebGL 2.0 ends ~10% below the baseline (4439–4605 → 3920–4149) and is not placed.** It is the only
  instrument that ends lower, but it scatters across neighbouring trees far beyond its between-boot
  spread (4255 at p03, 4713 at `b2`, 4674 at p05, 4271 at p06) and reads 3930 and 4267 on two boots of
  the same tree (`1fd19c2`, `s10`/`s11`). It steps down somewhere across p05..p07; single boots cannot
  place it finer.
- Everything after p07 is flat, including `d0416c9`'s fence-flush property, which this sweep runs
  with the property off (see *Method*).

## Basemark's scored run stalls, on some trees

The suite runs twice per boot and scores the second. On some boots that second run stops inside
Shader Pipeline: host GPU work falls to the idle desktop's trickle (~6 encoders a minute) and stays
there until the harness gives up, 15 minutes later. The renderer logs no refusal, poison or panic.
(Some stock guests also ignore `systemctl poweroff` afterwards, but scored ones did too, so that is
not a symptom of the stall.)

| tree | scored | stalled |
|---|---|---|
| p00 `0a9cf16` (twice) | 2 | 0 |
| p01 `58a29c9` | 1 | 0 |
| p02 `42008bb` (three times) | 3 | 0 |
| p03 `4afa3ef` (three times) | 2 | 1 |
| `7c65f0f` (`b2`) | 1 | 0 |
| `00657a4` (`b4`) | 0 | 1 |
| p04 `d30b8ce` | 0 | 1 |
| p05 `feef548` | 1 | 0 |
| p06 `4bfdefe` (three times) | 1 | 2 |
| `1fd19c2` with libkrun `0dba6b9c` (twice) | 2 | 0 |
| p07 `4654a34` (three times) | 3 | 0 |
| p08–p10 | 3 | 0 |

**It lives between the classic-fence rework and the next two fence changes:** 5 of 10 runs
stalled across p03..p06, none of 14 outside that window (p00..p02 over six boots, `1fd19c2`, p07..p10).
It opens with p02 → p03 (`0c38b13..4afa3ef` with libkrun `7c4ada0`) and closes in `4bfdefe..1fd19c2`,
whose only vrend commits are `39b0c68` and `1fd19c2` — the same two that return Canvas to the
baseline. A fence that sometimes covers too little, then waits on work nobody submits, would produce
exactly this shape; that is the lead, not a finding. `b1` (`894b36d`) also failed its scored run, but differently: the
host kept rendering at full rate until the timeout, so that page was busy, not waiting. It is kept out
of this table. One repeat (`s4`) measured nothing: the site never printed its configuration block,
and the harness refused to run.

## Method

- **Vehicle.** limina HEAD against each virglrs + libkrun pair, `cargo xtask build` (debug worker,
  renderer and its hot dependencies at opt-level 3). Host mesa `limina-kk` at the manifest's
  `5e99e7c` for every point — both the zink prefix and the KosmicKrisp build — so `351a1b5e` is held
  out. 4 vCPU / 4 GiB, display pinned to 1280x800 @ 1.0, fresh `cp -c` clones of
  `Fedora-Workstation-44.enhanced.raw` and `Fedora-Workstation-44.stock.test.raw` per boot, guest
  settled (uptime ≥ 200 s, 1-minute load < 0.3) before measuring. Driver: `trend-0a9cf16/point.sh`.
- **libkrun pairing.** Each point takes the libkrun its limina pin shipped with. `d0416c9` cannot
  build against the libkrun before `4c77915`, and `4c77915` tells it the host mesa submits fences
  without draining — true only on `351a1b5e`, and its own message says a libkrun on stock mesa must not
  claim it. p10 therefore builds `4c77915` with that property set false
  (`trend-0a9cf16/libkrun-4c77915-fences-drain.patch`).
- **Order within a boot.** Aquarium first, then perf-ledger ×3, then vkmark ×3. Before `42008bb` the
  first venus client to present poisons the compositor's vrend context (the SamplerView refusal
  `42008bb` fixes): the desktop flickers and every later number is not a measurement. A watchdog on the
  worker log marks rows taken after it INVALID. On every pre-fix tree that was vkmark, so aquarium and
  perf-ledger are clean there and vkmark has no baseline.
- **Basemark** uses one frozen copy of virglrs `d0416c9`'s `harness/vm/client-basemark.sh` for every
  point, since older trees predate it.
- **Resolution.** One boot pair per point. Read aquarium and Geometry/Canvas/Draw-call/SVG as
  instruments that resolve a step of this size; glmark2 (±10% between boots), WebGL 1.0.2 (11%) and
  Shader Pipeline (10.6%) only for moves well past that.
  Evidence: `trend-0a9cf16/evidence/<point>/`.
