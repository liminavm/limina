# Pin check: virglrs 828a05b → c76b2c7

**Subject:** virglrs `828a05b..c76b2c7`, 52 commits of venus command coverage (the generator and
the dispatch in `src/venus`, `venus-gen`) plus harness and fuzz work. No change to the C tree
virglrs pins, its `Cargo.lock` or `vendor.sh`. libkrun is held at `60746d3e` on both arms. Rows,
evidence and the driver: `perf/virglrs-2026-09-26/`; nothing went to `perf/ledger.csv`.

## What this pass can and cannot see

The bump adds commands the renderer decodes; it does not rework a path an existing workload
takes. So what this pass checks is that the venus and vrend instruments did not move. A command
no workload issues is invisible here.

**Display: 1280x800 at 59.97 Hz, scale 1.0, pinned in every guest** by `point.sh` (reboot pin,
`evidence/*/pin-*.txt`), with `perf-ledger.sh` checking the rate through `LIMINA_PERF_RATE=60`.

**The host was quiet.** The `gl-replay-llvmpipe` control stays within 729-747 at every point.

(`REFUSING to report: run 2 yielded no scores either`), the harness stall recorded in earlier
