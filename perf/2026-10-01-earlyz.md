# A/B: KK fragment lowering, limina's early-Z omission vs stock

**Subject:** limina-kk omits two fragment-shader lowerings that stock KosmicKrisp applies
(`kk_shader.c`, "limina: stock KK disables…"):

- `msl_disable_triangle_merge` for fragment shaders that need quad helper invocations;
- `msl_ensure_depth_write` when the shader may read a depth/stencil input attachment that the
  pipeline also writes.

The omission dates from when the triangle-merge lowering wrote a static sample mask, which forces
late-Z on Metal. Stock now prefers a barycentric colour select and keeps the sample mask only
for shaders with no colour output. Nobody had measured the early-Z cost of the barycentric form.

**Both arms ran one build:** host mesa `503b79ff61d` (limina-kk `285f2e97` plus a scratch lever),
virglrs `79fccb5`, libkrun `53522ebd` and limina `e2d02a9c`.

- The stock arm set `LIMINA_KK_STOCK_FS_LOWERING=1`, which restores both lowerings exactly as
  upstream gates them, including the M1/M2 multisample skip.
- The rows, the evidence and the driver are in `perf/earlyz-2026-10-01/`. Nothing went to
  `perf/ledger.csv`.

## What this pass can and cannot see

**The lever reaches nearly every textured fragment shader.** NIR marks a fragment shader as
needing quad helpers whenever it samples with implicit derivatives (`nir_gather_info.c`,
`gather_tex_info`), so every textured draw in the aquarium and in Basemark qualifies. The forced
depth write needs a depth input attachment, which these workloads are unlikely to use. This pass
therefore measures the triangle-merge half.

**The two arms really ran different code.** The lever logs once per process when it is armed, and
`point.sh` counts that line in each worker log (`arm-check.txt`). Every ours point counted 0 on
both guests, and every stock point counted 2. This proves the lever was live in the process, not
how many pipelines it rewrote; that count was not instrumented.

**Both guests matter here.** Unlike a zink-only change, the lowering sits in KK itself, so it
reaches the venus rows as well as the vrend ones.

**The host was quiet,** with one caveat. `gl-replay-llvmpipe` reads 658-709 across the pass,
about 5% below the 2026-09-28 pass. b2 sits highest at 697-700, so the host was quietest at the
end.

**No difference at this battery's resolution, in either direction.**

- The aquarium overlaps completely: 25k reads 43-50 with ours and 37-49 with stock; 30k reads
  36-43 with ours and 38-41 with stock.
- The venus rows agree across the arms within their own boot-to-boot spread. The first
  vk-replay run of a boot reads about 950-980 in b0 and n0, one of each arm, so it measures the
  boot, not the arm.
- The contended vkmark reads 990-1286 with ours and 997-1106 with stock. The ours points alone
  span 30%, so the arms cannot be separated.
- **Basemark shader pipeline is the one row ordered by arm.** Ours reads 1520-1580 and stock
  1445-1490, 2-9% lower. With one sample per point this is a lead, not a result. Basemark's
  other WebGL rows show no such ordering.
- Basemark's second run scored on all five points. No watchdog (poisoned-context) marker
  appeared in any worker log.

**What this means for the omission:** against stock's current barycentric form, limina's
omission buys no measurable early-Z win on these workloads. Its cost, incorrect edges where
Metal merges triangles under helper invocations, has not been measured either. It stays a known
divergence from upstream.

## Vehicle

- Worker: a debug build with the dev `opt-level = 3` overrides, built by `point.sh` at every point
  from the same tree. The arms differ only in environment, plus a separate shader cache per arm
  (`work.noindex/shader-cache-{ours,stock}`) so that neither arm reads the other's binaries.
- Boot: EFI+venus (`boot-enhanced-efi-kk.sh`), 4 vCPU / 4 GiB, `--display-resolution 1280x800`,
  with the guest display pinned by `point.sh`.
- Enhanced image: `Fedora-Workstation-44.enhanced.raw` (kernel `7.1.8-limina16k.4`,
  `mesa-dri-drivers-26.1.8-11.limina`).
- Stock image: `Fedora-Workstation-44.stock.test.raw`.
- The aquarium fps figures were read by eye off `evidence/<label>/aquarium-r*/*-fps.png`.
