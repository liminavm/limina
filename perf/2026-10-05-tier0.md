# A/B: latency-QoS tier 0 on every vCPU

**Subject:** the supervisor's `LIMINA_VCPU_LATENCY_QOS=0` default (limina `88b29e8b`, mechanism in
libkrun `34fbcdec`), against the same tree with it set empty (off; the band on vCPU 0 runs in both).
- **Host:** limina-kk `2315d532b3d` (the 3D-array mip fix); virglrs `b91824b`; libkrun `34fbcdec`;
  limina `a4e59ce2`.
- **Guest:** enhanced F44, mesa `26.2.3-3.limina`, kernel `7.1.13-limina16k`; 4 vCPUs, 4 GiB,
  1280x800 @ 1.0, 60 Hz.

Drivers, rows and evidence are in `perf/tier0-2026-10-05/`; nothing went to `perf/ledger.csv`.

## What this pass can and cannot see

- **The arms differ only in one variable.** Each point's `vcpu-qos.txt` proves it: the off points
  log no vCPU at a tier, the tier-0 points log every vCPU (twice, because the display pin reboots
  the worker).
- **Order:** o0 t0 o1 t1 o2, so the baseline is measured at both ends.
- **Host health:** the `gl-replay-llvmpipe` control read 725-736 throughout, so the host was quiet.
- **Logs:** no point aborted or wedged, and no worker log has a poisoned-context line.
- **What it does not isolate:** the KK and virglrs bump. Against `perf/rebase-2026-10-02/`, the
  guest's mesa also moved (26.2.3-2 to -3), so that difference cannot be split between the three.

## Results

Five points, one boot each, measured 2026-10-05:

| workload | off (o0 o1 o2) | tier 0 (t0 t1) |
|---|---|---|
| gl-replay-llvmpipe (control) | 736 735 725 | 731 732 |
| **gl-replay-venus** | **45.8 45.9 45.7** | **51.0 50.9** |
| vk-replay-venus-headless | 2300 2253 2337 | 2372 2341 |
| glmark2-wayland-venus | 2839 2843 2854 | 2855 2854 |
| vkmark-default-venus | 3120-3132 (9 runs) | 3128-3138 (6 runs) |
| aquarium 25k (vrend) | 51 46, 50 50, 45 50 | 46 47, 47 49 |
| aquarium 30k (vrend) | 38 38, 43 39, 43 39 | 38 38, 39 40 |

- **Tier 0 makes gl-replay-venus 11% faster**: 50.9-51.0 against 45.7-45.9, with no overlap, and
  both off ends agree. This is the instrument the ledger had never seen move. It replays through
  Xwayland, whose present path waits on wakeups, so it is the battery workload nearest to the frame
  pacing tier 0 fixes.
- **Nothing else moves.** vk-replay, glmark2 and vkmark sit inside their spreads (vkmark within
  0.3%), and the aquarium is the same in both arms. Throughput-bound work does not wait on timers,
  so tier 0 neither helps nor costs it.
- **Today's host against 2026-10-02**: vk-replay matches, gl-replay-venus is up slightly
  (45.7-45.9 against 43.9-45.1), glmark2 is down about 3.5% (2839-2854 against 2921-2976), and
  vkmark is down about 5% (3120-3132 against 3290-3308). The control is in range on both days.
  Three things moved in between, and two are ruled out for vkmark: virglrs `d505e48..b91824b`
  touches only vrend, and the KK commit changes only 3D images created 2D-array-compatible, which
  vkmark does not make. Tier 0 is ruled out too, because today's off arm reads the same. That leaves
  the guest mesa bump (26.2.3-2 to -3) as the lead; it is not measured.
