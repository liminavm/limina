# swsusp (Linux suspend-to-disk / S4) — reference notes for M9

Condensed from a 2026-06-28 research pass (sources at the bottom). VERIFIED = cited; ASSUMED = inference.

## The model (why guest-side S4 fits limina)

limina's plan — guest writes its own RAM image to a virtio-blk swap, PSCI `SYSTEM_OFF`s the worker, a
**fresh** worker cold-boots and resumes — **is the canonical bare-metal hibernation flow** with "BIOS
powerdown" → PSCI SYSTEM_OFF (worker exit) and "next power-on" → spawn a fresh worker. The kernel can't
tell the difference. It needs **no VMM state serialization**: the guest's swsusp owns 100% of the saved
state, on the persistent disk, surviving worker exit / app quit / host reboot. **[VERIFIED]**

## Sequence (`echo disk > /sys/power/state` / `systemctl hibernate`)

1. freeze userspace + freezable kernel threads (the freezer; a task that won't freeze aborts it).
2. device `.freeze` (quiesce). 3. atomic snapshot of the in-use working set, IRQs off (⇒ needs ~½ RAM
free). 4. device `.thaw` (so the image can be written). 5. write (compressed — LZO default; LZ4
selectable since 6.9) image to swap. 6. device `.poweroff`. 7. power down (mode from `/sys/power/disk`;
use **`shutdown`** — no firmware S4 in libkrun/EDK2). **[VERIFIED]**

## Resume handshake

swsusp overwrites the swap header's magic with a hibernation signature + image pointer. The resuming
kernel, **before mounting any filesystem** (so: from the initramfs / a lateinit hook), reads the resume
device's page 0; signature present ⟹ load image into free RAM, **atomically copy back to original
physical pages**, restore CPU/device state via `.restore`, thaw — execution continues *inside the
hibernated kernel*. Signature absent/invalid ⟹ ordinary boot (the graceful either/or). **[VERIFIED]**

Triggers: `resume=<dev>` (+ `resume_offset=<n>` for a swapfile) on the cmdline (lateinit), or the
initramfs writes the dev to `/sys/power/resume` (dracut `resume` module). systemd also records a
`HibernateLocation` **EFI variable** — but **libkrun almost certainly does not persist an EFI varstore
across a worker restart**, so M9 must use the **cmdline** path. **[VERIFIED + spike-confirmed setup]**

## The must-match rule (load-bearing)

The resuming kernel must be the **byte-identical build** as the hibernating one. The generic header
(`swsusp_info`) checks `LINUX_VERSION_CODE`, full `utsname` (incl. build string/date), `num_physpages`
(⇒ **same RAM size**), CPU count, and **`PAGE_SIZE`**; arm64 adds an arch header checking `uts_version`
("Hibernate image not generated by this kernel!"). So: **same kernel, same page size (4k vs 16k cannot
cross), same `--ram-mib`.** A swapfile `resume_offset` is in PAGE_SIZE units (differs 4k vs 16k for the
same byte position). Any mismatch ⟹ falls back to cold boot. **[VERIFIED]**

## Swap

Partition or file. Swapfile needs `resume_offset` (FIBMAP/bmap; on **btrfs** use
`btrfs inspect-internal map-swapfile -r <f>` — `filefrag` is wrong). btrfs swapfile must be NODATACOW +
preallocated + single-device + on an un-snapshotted subvol (`btrfs filesystem mkswapfile` does it).
Size ≥ RAM is safe (systemd also refuses if swap < `Active(anon)`; bypass via
`SYSTEMD_BYPASS_HIBERNATION_MEMORY_CHECK=1`). **zram can NEVER hold the image** (it's RAM-backed →
circular) — and Fedora ships **zram-only swap by default**, so a stock guest can't hibernate until real
swap is added. **[VERIFIED]**

## arm64 specifics

Supported (`ARCH_HIBERNATION_POSSIBLE`). `swsusp_arch_resume` builds an identity/trampoline page-table
in TTBR0 and copies the restore code to a safe exec page, with heavy cache maintenance to PoC/PoU. A
non-VHE EL1 guest (libkrun) skips the EL2-vector dance. The classic bare-metal failure mode (boot kernel
places memory differently than the image expects) is **dodged by limina's deterministic memory layout**
— *provided the resuming worker is configured identically (RAM size!)*. **[VERIFIED / ASSUMED]**

> ⚠️ **Spike caveat (2026-06-28, `RESULTS.md`):** the arm64 CPU-suspend path also touches PSCI `CPU_OFF`
> (offline non-boot CPUs) and EL1 **debug** sysregs (OSDLR_EL1, …) — both currently unhandled by
> libkrun's HVF backend, which is what actually blocks S4 today. Page-size/RAM matching is necessary but
> not sufficient.

## virtio across hibernate

`virtio_pci`/`virtio_mmio` implement `.freeze`/`.restore` under `CONFIG_PM_SLEEP` (libkrun = mmio →
`virtio_mmio_restore`). `virtio_device_restore` **resets, re-reads config, re-negotiates features,
rebuilds queues, re-sets DRIVER_OK** — i.e. brings the device up as if freshly probed. **This is why a
brand-new VMM worker can satisfy resume**: the guest assumes no carried-over queue state. Requirement:
the resuming worker presents the **same device topology + ≥ same feature bits**. Clean for
blk/net/console/balloon/vsock; **virtio-gpu is the exception** — host resources die with the old worker,
so the enhanced 3D tier needs the out-of-tree drm/virtio freeze/restore resubmit series (Dongwon Kim,
v5, *not upstream*), and the stock tier should simply not assume GPU state survives. **[VERIFIED]**

## limina-side must-dos on resume

- **Wall clock**: swsusp restores the kernel's *saved* time; there's **no `/dev/rtc` from macOS**, so the
  clock is frozen at pre-hibernate time until corrected. M9 must push host time via `limina-agent`
  (the port-123 timesync already fires on long-sleep detection — no consumer yet). **[VERIFIED]**
- Keep `CONFIG_HIBERNATION`/`CONFIG_PM_SLEEP` in the 16k kernel; keep the guest **not** Secure-Boot
  lockdown'd (lockdown blocks hibernation to unencrypted swap). **[VERIFIED]**

## Failure modes that make `systemctl hibernate` silently refuse

zram-only swap; systemd `Active(anon) > swap` heuristic; `/sys/power/resume` ≠ `/proc/swaps`; swapfile
fragmented/in `/home`; **kernel lockdown (Secure Boot)**; missing `CONFIG_HIBERNATION`; freezer timeout;
**(spike-found) SELinux-unlabeled swap → logind `Access denied`**; **(spike-found) libkrun PSCI
CPU_OFF / EL1-sysreg gaps**. **[VERIFIED]**

## Debug aids

`/sys/power/pm_test` (`freezer|devices|platform|processors|core`) exercises the path without powering
off (needs `CONFIG_PM_DEBUG`); `dmesg | grep -i 'PM:\|hibernat\|resume'`. Verify a true resume vs cold
boot with a tmpfs marker file + a live process PID + the `boot_id` (all survive resume, none survive a
cold boot).
