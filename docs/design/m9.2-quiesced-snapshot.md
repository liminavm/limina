# M9.2 — the quiesced-invariant host-side snapshot (implementation plan)

> **STATUS: KICKOFF (2026-07-18).** Prereqs proven this session: B3 stock no-agent suspend trigger
> (libkrun 0060/0061), Spike F PL031 wake, the 0058 virtio thaw hardening + balloon F_REPORTING mask,
> B4 clock-preservation, and the three-button GPIO lifecycle. This doc turns the re-scoped
> **quiesced-invariant** contract (chosen 2026-07-17) into a build plan. Ground truth for the M9.1
> mechanism it builds on: `docs/design/m9-suspend-resume.md` §M9.1 and [[limina-m9-suspend-resume]].

## The core idea (why this is tractable now)

M9.1 snapshots a **running** guest: vCPU + GIC + RAM are restored into a fresh worker and the guest
resumes at its exact PC — but its **virtio devices are dead** (fresh backends never saw the guest's
queue setup), so it wedges on the first device touch. Serializing full virtio device state is the
expensive path we're avoiding.

Instead M9.2 makes the guest **quiesce itself first**. The supervisor pulses the **suspend button**
(B3) → the guest's own PM path runs → logind → s2idle → every virtio driver's `.suspend` callback
**drains its queues and resets the device to a clean state**. We snapshot *that* quiesced machine. On
restore, the fresh worker reloads RAM+vCPU+GIC and **injects the PL031 wake**; the guest runs its own
s2idle `.resume` path and **re-initialises every virtio device from scratch** (the exact `0x0→…→0xf`
re-init ladder the 0055–0058 thaw hardening already makes work). Devices come back **live** — no
host-side device schema needed. The snapshot's only device-state invariant: **queues are quiesced
(INIT), nothing in flight.** That is the contract we *assert*, not serialize.

```
SUSPEND (host-driven):
  supervisor → worker: pulse suspend button (SIGUSR2 → KEY_SLEEP)
  guest: logind → echo freeze → virtio .suspend drains queues → vCPUs park in s2idle WFI
  worker: QUIESCE ORACLE fires (all vCPUs idle + devices quiesced) [timeout → ABORT: inject wake, resume]
  worker: assert INIT-invariant (queues quiesced, exception list) → save_snapshot → exit 126
  supervisor: persist Suspended{snapshot} → teardown (frees host RAM)

RESTORE (later start):
  fresh worker --restore: reload RAM+vCPU+GIC (M9.1) → arm+inject PL031 wake
  guest: s2idle .resume → virtio re-init ladder (0058) → devices LIVE → continues
```

## The RED acceptance test (defines the milestone)

`crates/limina-test/tests/l1_snapshot.rs` — a new test
`l1_counter_survives_quiesced_snapshot_and_restore` that asserts the **continuity M9.1 deferred**:
boot the counter guest, sample `(pre_n, pre_mono)`, run the **host suspend bracket**, restore into a
fresh worker, and assert the guest **keeps running with live devices** — the heartbeat continues
(`post_n ≥ pre_n`, `post_mono ≥ pre_mono`) **and a device touch works** (the counter guest's virtiofs
rootfs is alive post-resume; add a small "touch rootfs + emit a line" step to the counter mode, or use
a `--net` round-trip on a disk-booted guest). This is RED today (M9.1 wedges on device touch).

Keep the M9.1 mechanism guards (`…_save_writes_file_and_exits_126`,
`…_resumes_in_fresh_worker_from_snapshot`) green throughout — M9.2 is additive.

## Build order (each RED-first, boot-neutral where possible)

1. **Real macOS `resume_vcpus` (libkrun).** Today it's a no-op stub, which is why a failed save is
   fatal. M9.2 needs a genuine resume so the bracket can **abort** (failed quiesce/save → wake the
   guest → resume → report failure, guest survives). Pairs with the pause wiring M9.1 added
   (`VcpuEvent::Pause/Resume`, `kick_all`). This is the keystone for "non-fatal failed-save."
2. **Quiesce oracle + timeout (worker).** Detect the guest reached s2idle-quiesced: all vCPUs parked
   in the idle WFI + no virtio queue in a non-INIT/in-flight state. Expose as a predicate the
   snapshot-trigger thread waits on (bounded timeout → abort via step 1). Decide the signal: poll vCPU
   run-state + device status, or a lightweight "entered s2idle" tell from the guest console/PSCI.
3. **INIT-invariant assert + exception list (worker).** At save time, assert every virtio-mmio device
   is quiesced (queues drained), with a named exception list for devices that legitimately aren't fully
   INIT under s2idle. Fail-closed → abort (step 1), don't snapshot a mid-flight machine.
4. **Wake-injection on restore (libkrun + worker).** After M9.1 restore, arm+fire the PL031 alarm (or
   inject its IRQ directly) so the guest exits s2idle and runs its `.resume` path. Reuse the 0054 alarm
   + the restore gate ordering. Also used by the abort path (step 1).
5. **Suspend bracket in the supervisor.** Sequence: pulse suspend button → wait quiesce (worker
   reports ready, or a control-plane ack) → trigger snapshot (existing SIGUSR1) → persist
   `Suspended{snapshot}` → teardown. Add a **liveness timeout** around the whole bracket (guest never
   quiesces / never resumes → abort + report, never hang). Wire it to a `limina suspend <vm>` verb /
   the control-center action.
6. **Clock on restore.** B4 proved the guest's `timekeeping_resume()` re-reads PL031 and self-corrects
   for free *if the fresh worker's PL031 reports current wall time* — depends on the scoped PL031
   wallclock fix ([[limina-guest-clock]]). Verify end-to-end; add a one-shot step only if the fresh
   worker's RTC is `Instant`-anchored.

## Key risk to de-risk first

**Does s2idle-in-place compose with the host-side snapshot-and-teardown?** M9.1's vCPU save uses the
per-vCPU `Snapshot` event to self-quiesce; M9.2 wants the vCPUs already parked in the s2idle idle loop
*before* the snapshot fires. The saved vCPU state is then "in the s2idle wait," and the injected wake
must bring it out on restore. Both halves work independently (B3 s2idle; M9.1 snapshot); **composing
them is the first thing to prove** — a focused spike (suspend button → confirm vCPUs parked → snapshot
→ restore → inject wake → guest continues) before wiring the full bracket. If the composition needs
the snapshot to fire *from inside* the s2idle wait, that shapes steps 1–2.

## Two-tier note

Stock and enhanced now share the **same quiesce mechanism** (B3 suspend button — no agent needed), so
the M9.2 device-continuity contract applies to both tiers. The tier split is only the **GPU**
resubmit/replay (M9.3): stock accepts the re-init blip; enhanced rides the guest's own resume path.
