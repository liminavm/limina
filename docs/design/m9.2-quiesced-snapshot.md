# M9.2 — the quiesced-invariant host-side snapshot (implementation plan)

> **STATUS: KICKOFF (2026-07-18).** Prereqs proven this session: B3 stock no-agent suspend trigger
> (libkrun 0060/0061), Spike F PL031 wake, the 0058 virtio thaw hardening + balloon F_REPORTING mask,
> B4 clock-preservation, and the three-button GPIO lifecycle. This doc turns the re-scoped
> **quiesced-invariant** contract (chosen 2026-07-17) into a build plan. Ground truth for the M9.1
> mechanism it builds on: `docs/design/m9-suspend-resume.md` §M9.1 and [[limina-m9-suspend-resume]].

## The core idea (why this is tractable now)

M9.1 snapshots a **running** guest: vCPU + GIC + RAM are restored into a fresh worker and the guest
resumes at its exact PC — but its **virtio devices are dead** (fresh backends never saw the guest's
queue setup), so it wedges on the first device touch. Serializing full virtio device state is the
expensive path we're avoiding.

Instead M9.2 makes the guest **quiesce itself first**. The supervisor pulses the **suspend button**
(B3) → the guest's own PM path runs → logind → s2idle → every virtio driver's `.suspend` callback
**drains its queues and resets the device to a clean state**. We snapshot *that* quiesced machine. On
restore, the fresh worker reloads RAM+vCPU+GIC and **injects the PL031 wake**; the guest runs its own
s2idle `.resume` path and **re-initialises every virtio device from scratch** (the exact `0x0→…→0xf`
re-init ladder the 0055–0058 thaw hardening already makes work). Devices come back **live** — no
host-side device schema needed. The snapshot's only device-state invariant: **queues are quiesced
(INIT), nothing in flight.** That is the contract we *assert*, not serialize.

```
SUSPEND (host-driven):
  supervisor → worker: pulse suspend button (SIGUSR2 → KEY_SLEEP)
  guest: logind → echo freeze → virtio .suspend drains queues → vCPUs park in s2idle WFI
  worker: QUIESCE ORACLE fires (all vCPUs idle + devices quiesced) [timeout → ABORT: inject wake, resume]
  worker: assert INIT-invariant (queues quiesced, exception list) → save_snapshot → exit 126
  supervisor: persist Suspended{snapshot} → teardown (frees host RAM)

RESTORE (later start):
  fresh worker --restore: reload RAM+vCPU+GIC (M9.1) → arm+inject PL031 wake
  guest: s2idle .resume → virtio re-init ladder (0058) → devices LIVE → continues
```

## The RED acceptance test (defines the milestone)

> **⚠️ The counter guest CANNOT be the vehicle (Fable review 2026-07-18).** It has a **virtiofs
> rootfs**, and upstream `virtio_fs_freeze` returns `-EOPNOTSUPP` (`fs/fuse/virtio_fs.c`), so **s2idle
> aborts inside the guest** on any mounted virtiofs — the bracket never quiesces it. Use a **disk-booted
> stock guest with `--net`** and an SSH/heartbeat oracle instead. (Corollary, tracked separately: **any
> VM with an M5 virtiofs share can't suspend on a stock kernel** — so the bracket's *abort* path is a
> common case, and an enhanced-tier `virtio_fs` freeze/restore kernel patch, à la `patches/linux/0005`,
> is candidate follow-up.)

A new test asserts the **continuity M9.1 deferred**: boot a disk-booted `--net` guest, sample a
liveness token, run the **host suspend bracket**, restore into a fresh worker, and assert the guest
**keeps running with live devices** — an SSH round-trip + outbound `curl` succeed post-resume (virtio-net
+ virtio-blk re-init'd via the 0058 thaw ladder). RED today (M9.1 wedges on the first device touch).

Keep the M9.1 mechanism guards (`…_save_writes_file_and_exits_126`,
`…_resumes_in_fresh_worker_from_snapshot`) green throughout — M9.2 is additive.

## Build order (each RED-first, boot-neutral where possible)

1. **Real macOS `resume_vcpus` (libkrun).** Today it's a no-op stub (`vmm/src/lib.rs:321`), which is
   why a failed save is fatal. M9.2 needs a genuine resume so the bracket can **abort** (failed
   quiesce/save → wake the guest → resume → report failure, guest survives). Pairs with the pause wiring
   M9.1 added (`VcpuEvent::Pause/Resume`, `kick_all`). **Trap (Fable):** `start_vcpus` calls
   `resume_vcpus` on **every** boot (`lib.rs:296`), and the macOS run loop swallows a stale `Resume`
   without replying `Resumed` (`macos/vstate.rs:553`) while only *parked* vCPUs (`handle_pause`,
   `handle_snapshot`) respond — so a Linux-style wait-for-`Resumed` impl would hang cold boot. The impl
   must only await responses from vCPUs it knows are parked. Keystone for "non-fatal failed-save."
2. **Quiesce oracle + timeout (worker).** Detect the guest reached s2idle-quiesced: all vCPUs parked
   in the idle WFI + no virtio queue in a non-INIT/in-flight state. Expose as a predicate the
   snapshot-trigger thread waits on (bounded timeout → abort via step 1). Decide the signal: poll vCPU
   run-state + device status, or a lightweight "entered s2idle" tell from the guest console/PSCI.
3. **INIT-invariant assert + exception list (worker).** At save time, assert every virtio-mmio device
   is quiesced (queues drained), with a named exception list.
   - **✅ PREMISE CONFIRMED (2026-07-18, `spikes/m9-freeze-trigger/observe-quiesce-status.sh`).** At
     s2idle-quiesce **every** virtio-mmio device reads `device_status = 0x0` (INIT) — verified on a
     headless stock-F44 `--net` boot: blk(root), vsock, snd, net(eth0), console(hvc0), balloon, rng,
     i2c(battery) all 0x0. The driver `.suspend` callbacks fully reset each device, so the oracle is
     simply **`device_status == 0` for every virtio-mmio device except virtio-gpu**. (Read via the new
     `MmioTransport::device_status()` accessor + `MMIODeviceManager::virtio_statuses()`; the
     `Vmm::quiesce_holdouts()` / `is_quiesced()` oracle filters out virtio type 16.) This matches the
     3s-after-freeze settle the GREEN restore round-trip already used.
   **Known required exception: virtio-gpu**
   — upstream virtgpu has **zero PM ops** (no freeze/restore through ≥v6.15), so it stays `DRIVER_OK`
   (0xf) with configured queues across s2idle. So M9.2 is **headless-scoped** (windowed GPU restore is
   M9.3); the assert excepts virtio-gpu. Read status via `MMIODeviceManager::get_device_info()` +
   `device_status` (needs a one-line accessor). Fail-closed → abort (step 1), don't snapshot a
   mid-flight machine.
4. **Wake mechanism = a `wakeup-source` GPIO button, NOT PL031 injection (Fable review; validated
   2026-07-18).** An s2idle guest only wakes on a `wakeup-source`-armed irq; the bracket arms no
   wakealarm, the fresh worker's PL031 is masked (`imsc=0`, regs not serialized), and a plain injected
   IRQ is masked-while-suspended → **no wake**. Fix (libkrun 0062, shipped): a fourth gpio-keys button
   (`KEY_WAKEUP`, line 6, `wakeup-source`) + wake eventfd; the worker pulses it after restore. **In-place
   validated** (`spikes/m9-freeze-trigger/wake-spike.sh`): wakeup-source button wakes s2idle, a non-wake
   button doesn't. **Restore still needs a tiny legacy-device register section in LIMINAS1** (PL061
   `data/dir/im/istate/isense/ibe/iev` + PL031 `imsc/match/ris`, ~40 bytes), restored into the fresh
   devices **before** vCPUs run — else the fresh PL061 `im=0` won't demux the injected wake
   (`GPIOMIS = istate & im`) and the guest re-freezes. This is **not** the virtio device-schema cost we
   avoid. **Injection point:** after `restore_gic_state` + gate open + an **all-vCPUs-restored ack**
   (each restoring vCPU sends `Resumed` after `restore_state`; builder waits) — never assert into an
   unready GIC. Also used by the abort path (step 1).
5. **Suspend bracket in the supervisor.** Sequence: pulse suspend button → wait quiesce (worker
   reports ready, or a control-plane ack) → trigger snapshot (existing SIGUSR1) → persist
   `Suspended{snapshot}` → teardown. Add a **liveness timeout** around the whole bracket (guest never
   quiesces / never resumes → abort + report, never hang). Wire it to a `limina suspend <vm>` verb /
   the control-center action.
6. **Clock on restore.** B4 proved the guest's `timekeeping_resume()` re-reads PL031 and self-corrects
   for free *if the fresh worker's PL031 reports current wall time* — depends on the scoped PL031
   wallclock fix ([[limina-guest-clock]]). Verify end-to-end; add a one-shot step only if the fresh
   worker's RTC is `Instant`-anchored.

## Key risk to de-risk first

**Does s2idle-in-place compose with the host-side snapshot-and-teardown?** M9.1's vCPU save uses the
per-vCPU `Snapshot` event to self-quiesce; M9.2 wants the vCPUs already parked in the s2idle idle loop
*before* the snapshot fires. The saved vCPU state is then "in the s2idle wait," and the injected wake
must bring it out on restore.

- **✅ SAVE half — PROVEN (2026-07-18, `spikes/m9-freeze-trigger/m92-comp-save.sh`).** Stock F44 EFI +
  `--snapshot-file`: pulse the suspend button (SIGUSR2 → KEY_SLEEP) → guest s2idles (SSH drops in ~7s,
  no wake armed so it stays frozen) → trigger the snapshot (SIGUSR1) → **`save_snapshot` succeeds on the
  frozen guest**: worker exit 126, 2.15 GB file written. So the self-quiesce (`Snapshot` event +
  `kick_all`) **does reach vCPUs parked in the s2idle idle loop** — the composition's biggest unknown is
  resolved. No need to fire the snapshot "from inside" the s2idle wait; the existing SIGUSR1 path works
  on an already-quiesced guest.
- **✅ WAKE mechanism — PROVEN in-place (2026-07-18, `spikes/m9-freeze-trigger/wake-spike.sh`; libkrun
  0062).** The review busted the original "inject PL031 wake" (see step 4); the corrected wake is a
  `wakeup-source` `KEY_WAKEUP` gpio-keys button. In-place A/B on stock F44: suspend (no rtcwake) →
  frozen; **non-wake button → stays frozen**; **wakeup-source button → wakes** (`suspend exit`). So the
  wake *mechanism* is settled independent of any snapshot code.
- **✅ RESTORE half — GREEN (2026-07-18, `spikes/m9-freeze-trigger/restore-roundtrip.sh`; libkrun 0063).**
  Full round-trip on stock F44: boot → suspend button → s2idle → snapshot (+ PL061 register section,
  LIMINAS1 v2) → **worker exit 126 + teardown** → fresh worker `--restore` (same disk) restores
  RAM+vCPU+GIC+GPIO-registers, then injects the wake (`wake::pulse()` before the event loop). **The guest
  resumes with the SAME `boot_id` (resumed, not rebooted), `uptime` continuous, and LIVE devices** (SSH
  round-trips + outbound `curl` 200 — virtio-net/blk re-init'd via the 0058 ladder). SSH back within ~3 s
  of the restore boot. `PM: suspend entry (s2idle)` → `resume devices took 0.004s` → `suspend exit`.
  - The wake injection needed **no** all-vCPUs-restored ack in practice: the wake_efd is level-triggered
    and the raised SPI latches pending in the restored GIC, so it wakes the vCPU regardless of exact
    timing. (Kept as a hardening option if a race ever appears.)
  - Disk reused directly (worker had exited → no writes between save and restore); the APFS `cp -c`
    atomic-pair capture is still the right move once this is wired into the durable supervisor bracket.
- **✅ SUSPEND BRACKET + MANAGED FLOW — GREEN end-to-end (2026-07-18).** The full production path
  works through the real CLI verbs. Two proofs:
  - `spikes/m9-freeze-trigger/bracket-roundtrip.sh` — the **worker bracket** in isolation: ONE
    `SIGTSTP` to the worker pulses the suspend button, polls the quiesce oracle, snapshots, exits 126;
    a fresh `--restore` worker resumes the same `boot_id` with live net.
  - `spikes/m9-freeze-trigger/managed-suspend-roundtrip.sh` — the **managed VM** flow:
    `limina create --no-window` → `limina start` (bg) → `limina suspend` → `limina start`. `suspend`
    relays `SIGTSTP` to the supervisor → the bracket snapshots (2.1 GB) + tears down (worker 126) →
    the supervisor persists `[suspended]` to `state.toml`; the next `start` reads it, boots
    `--restore`, resumes the **same boot_id** with live net (curl 200), and **consumes** the record
    (`[suspended]` cleared). Balloon/dynamic-memory VM (exercises the 0059 F_REPORTING s2idle mask).

  Pieces landed: libkrun 0065 (quiesce oracle); worker `crate::bracket` (SIGTSTP → button → poll
  `is_quiesced` [20s timeout] → snapshot 126 / wake+abort) + `crate::suspend::pulse`; supervisor
  SIGTSTP handler + monitor relay with a 60s liveness timeout; `runtime::signal_suspend`; the
  `limina suspend <vm>` verb + `cmd_suspend`; `state.toml` `[suspended]` (`Suspended{snapshot}`,
  `set_suspended`) with arm-snapshot + consume-on-start wiring in `cli_from_definition`; run_vm
  persists on the 126 exit. The **INIT-invariant assert is the quiesce poll itself** (it never
  snapshots unless `is_quiesced`, GPU excepted) — so steps 2/3 collapse into the poll.
- **⏳ REMAINING:** promote `managed-suspend-roundtrip.sh` to an automated **L2 guard** in the harness;
  the **windowed** managed-VM persist (session.rs 126 branch — headless-only today; windowed is M9.3
  GPU-restore territory anyway); a **fault-injection** test for the bracket abort (guest that won't
  quiesce → wake + VM lives on); optional fail-closed re-check of `is_quiesced` inside `save_snapshot`
  (TOCTOU belt-and-suspenders; s2idle already guarantees no device activity between poll and save).

## Two-tier note

Stock and enhanced now share the **same quiesce mechanism** (B3 suspend button — no agent needed), so
the M9.2 device-continuity contract applies to both tiers. The tier split is only the **GPU**
resubmit/replay (M9.3): stock accepts the re-init blip; enhanced rides the guest's own resume path.

## What the guest must provide

The oracle asks the guest a question, so a guest can fail to answer it. Two requirements, both
learned from a stock guest rather than from the spec, and both about *drivers*, not about limina:

- **A driver must be bound to every virtio device we attach.** The guest's virtio core sets
  `ACKNOWLEDGE` on each device it registers, before any driver binds, and only a driver's
  `.suspend` writes the status back to `INIT` — `virtio_device_freeze()` never resets a device
  itself (verified identical in v6.12 and v7.1). So a device the guest has no driver for sits at
  `ACKNOWLEDGE` for the life of the VM. The oracle therefore keys on `DRIVER_OK`, not on
  `status != 0`: a device below `DRIVER_OK` has no queues in flight and nothing to wait for.
  Measured 2026-08-23 — a Debian 13 guest (6.12.101) had no driver for our virtio-i2c SBS battery
  and could never be observed to quiesce; Debian 14 (7.1.8) ships the driver, whose
  `virtio_i2c_del_vqs()` calls `virtio_reset_device()`.

- **Suspend needs a guest kernel ≥ 6.17**, because of virtio-input. Before
  `528d92bfc093 "virtio_input: Improve freeze handling"` (first released in v6.17),
  `virtinput_freeze()` cleared `vi->ready` and deleted the virtqueues but never reset the device,
  so the input devices stayed `DRIVER_OK` through an s2idle the rest of the guest completed. It
  was never backported to 6.12.y — that file is untouched on `linux-6.12.y` since 2024-07-08 —
  so an LTS-kernel guest does not grow into it. Measured 2026-08-23: Debian 13 (6.12.101) held out
  on all three input devices and the bracket aborted at the 20 s deadline; the same VM upgraded to
  Debian 14 (7.1.8) quiesced in **252 ms** and snapshotted, under the *older* `status != 0` oracle.

Neither is limina's to fix in the guest, and neither degrades anything else: a guest that cannot
quiesce keeps running, because the bracket wakes it and aborts. Suspend is the one feature with a
guest-kernel floor.
